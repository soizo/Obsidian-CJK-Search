# Find / Open file 搜索增强设计

状态：设计及[实施计划](../plans/2026-09-22-find-open-file.md)均获用户批准。0.2.0 已实现、完成桌面验收与作者自审，并安全更新批准测试库；无子代理或 Git 操作。最新证据、覆盖层级及剩余限制见[验证报告](../../research/find-open-file.md)。iOS 新入口待用户复测。

## 1. 目标与已确认事实

- 用户确认 macOS 与 iOS / Obsidian 1.13.7 的全库搜索符合预期。此前手机失败报告实际来自当前笔记 Find 和文件名搜索；不再将其作为全库插件故障修复。
- 全量兼容改为默认开启：新安装或未保存此项时为 true，已保存的布尔值（包括 false）保持不变。无一次性强制开启迁移，不覆写其他设置。
- 在原生 **Find…（当前 Markdown 笔记）** 和 **Open file…（⌘O 快速切换器）** 中增加同一套字符等价能力。
- 保留输入、文件名、正文、原生界面、结果高亮及跳转；Find 暂不扩大任何替换操作的匹配范围。
- Unicode 18.0.0 / OpenCC 1.4.2 的数据选择、跨义项闭包及许可证不变。默认策略变化不需要重抓上游或改变数据表。

“关闭全量兼容”仅关闭本插件额外提供的全量关系，**不反向禁用某个原生入口本来就支持的兼容匹配**。三个入口采用各自原生语法，并不承诺它们的基础搜索行为完全相同。

## 2. 范围

| 入口 | 本轮覆盖 | 保留原生的范围 |
| --- | --- | --- |
| 全库搜索 | 保持现有适配，更新默认设置及回归 | 原有复杂查询语法和超限回退 |
| Find | 顶层 Markdown 笔记的编辑／实时预览与阅读模式；普通文字、前后跳转和计数 | 正则、替换模式；PDF、网页、Canvas、Bases、嵌入编辑器等其他视图 |
| Open file | 原生快速切换器现有候选中的文件名／路径及文件别名 | 空查询最近文件、未解析链接、非文件书签及创建文件行为 |

仍只用一个全量兼容开关，不增加每入口独立开关。字符规则在三个入口共用；查询语法不能照搬全库规则：Find 中的空格是字面内容，文件名中的空格或连字符也不能被误当成全库操作符。

## 3. 已核实的原生结构

通过只读检查本机 Obsidian 1.13.7 的打包源码得到，尚不等同于新适配已实测：

- `editor:open-search` 调用当前编辑器／视图的 `showSearch(false)`；替换命令传 true。
- Markdown 编辑查找组件保存 `isReplace`，通过 `getQuery()` → `editor.searchCursor(...)` 创建游标；替换也使用该游标。因此不能无条件增强所有游标。
- Markdown 阅读模式使用另一查找对象，对渲染后的各段文本生成 `{section,start,end,active}` 范围，原生负责高亮及选择范围。编辑和阅读需要各自适配，不能直接复用全库的 renderSearchInfo 钩子。
- `switcher:open` 创建原生快速切换器；建议生成器枚举原生 vault 文件及 metadataCache 别名，执行模糊／简单匹配，再排序。原生还处理文件类型选项、忽略规则降权、最近文件、书签、未解析链接及创建文件。
- 上述构造器在打包源码中的压缩名称不是稳定接口；实现不得把这些名称硬编码进插件，也不复制整套 Obsidian 私有实现。

## 4. 方案选择

采用 **共享现有字符数据 + 两个针对原生入口的适配器**。

不采用：

1. 改写输入框、文件名或笔记正文：违反原文与输入不变的约束。
2. 为这些入口另造搜索 UI 或常驻笔记索引：重复原生能力，增加同步、排序和生命周期负担。
3. 给全局 String、RegExp 或所有 Editor 搜索打补丁：影响其他功能／插件，尤其可能扩大替换范围。

建议代码职责：`src/matcher.js` 提供可复用的等价关系与原文偏移能力；新增 `src/find.js`、`src/open-file.js` 分别处理两个真实入口；`src/main.js` 只负责设置、生命周期及日志接入。不引入抽象适配器框架或 UI 依赖。

## 5. 共享匹配与偏移

- 保留现有全库 `expand` 行为；将普通字面匹配核心与全库语法检测分离，供 Find 使用，不让全库正则／操作符突然获得新含义。
- Open file 的匹配不是连续子串正则，不能把文件名搜索直接替换成现有正则展开。使用同一模式的规范键处理查询及候选的临时字符串，再使用原生匹配能力。
- 对候选的每个规范化片段保留原始 UTF-16 起止位置，映射回原始文件名／别名用于高亮。一个源字符分解成多个字符时，任意命中片段都映射到完整源字符；相邻／重复范围合并，非 BMP 不拆代理对。
- Find 直接在原文或原生阅读文本上匹配，输出原文范围；不把规范串中的位置直接用于编辑器或 DOM。
- 继续限制输入、模式长度和展开工作量；失败回退整个入口的本次原生行为，不悄悄截断候选。Open file 不展开查询变体的笛卡尔积，也不为每个变体反复全库枚举。
- 不创建常驻文件／笔记索引；只读取原生已经维护的文件和元数据，计算当次必要的临时匹配信息。

## 6. Find 适配

### 编辑与实时预览

只在原生查找对象处转换内部匹配器，保留搜索框内容及模式按钮。普通查询用共享等价匹配，前后导航、选择、高亮和计数继续消费原生游标。

正则识别以该入口的原生解析结果为准，不自行把阅读模式中的斜杠文本解释为正则。检测到原生正则或替换模式时完全走原生流程。由 Find 切换到替换时必须重新建立原生游标；替换按钮／快捷键不能意外复用之前的增强游标。关闭、切换文件／模式及卸载时清理增强状态。

若直接换成正则游标会丢失该入口原有的兼容／大小写匹配，不能以“关闭全量”为由接受回归：保留原生匹配再补充等价结果，按原文范围去重、排序；或找到能保留原生语义的更小接入点。不得靠永久开启 full 数据来假装保留原生语义。

### 阅读模式

使用原生渲染文本的段落边界与范围结构，只改变命中范围的生成；计数、上下条、高亮和滚动沿用原生。不能用 Markdown 源码偏移替代阅读 DOM 偏移，不能重写 DOM 文本来制造命中。

实施时先核对原生文本节点收集规则与高亮坐标是否一致；若无法可靠映射，就报告该入口不可兼容，不以视觉上“差不多”验收。

## 7. Open file 适配

保持原生快速切换器和返回的真实文件对象；新命中仍打开原文件，不能把规范化名称用于打开、创建、重命名或链接解析。

- 普通查询保留原生命中，补充等价字符命中；去重时优先保留原生结果。同一文件的不同别名不随意压成一个结果。
- 使用原生模糊／简单匹配的评分语义合并补充结果，不把模糊搜索降级为连续 substring，也不自建相关度算法。原生命中的分值不改写；新增结果可能改变显示位置。
- 文件名／路径、别名高亮映射回原文；原生候选过滤、忽略降权及文件类型选项必须有对应回归。
- 空查询直接沿用最近文件；未解析链接和非文件书签本轮不追加等价命中。保持其原生命中及创建动作。
- 不为了补充候选临时改写 app.vault、metadataCache 或实际 TFile 对象；不能影响其他入口／插件的读取。

如果原生候选资格或评分行为不能用有限适配可靠保留，先报告具体差异并重新审查这一部分，不悄悄复制整个建议生成器或削减已确认范围。

## 8. 生命周期、设置及故障

- 只给目标实例安装必要钩子，覆盖已打开／后打开的笔记和快速切换器；处理延迟加载、模式切换及组件重建，避免重复包装。
- 卸载只恢复仍由本插件拥有的方法，不覆盖其他插件后来安装的包装。
- 对未加载的占位视图不直接认定“移动端不兼容”；实际接入失败按入口明确记录。
- 保留 `[CJK-Probe]` 前缀，增加入口标识及失败类别；不记录查询、笔记、路径、文件名或别名。成功安装钩子不等于已发生匹配。
- 默认 true 的逻辑只放在设置解析层；已保存 false 保留。非法值退回默认并记录类别；设置读取失败使用默认并提示，不自动覆写原文件。
- 改变开关影响下一次输入或重新打开搜索，不宣称立即重算所有既有结果。

## 9. 验收与交付

先用失败测试固定新能力，再实现。既有完整数据测试、全库原生回归、设置保留与安全安装检查全部保留。

新增最小验收：

1. 无设置默认 true；旧 true／false 不变，其他 data.json 字段不变。
2. 三入口的 `体／體`、`发／發／髮`、`弁` 组及反例；默认／全量差异以各入口未启用插件时的基线为准。
3. Find 的 `㍿／株式会社`、补充平面、重复命中、计数、前后循环；编辑与阅读模式分别验证原文高亮、输入不变和正文逐字节不变。
4. Find 空格及标点按字面搜索；正则保持原生。切入替换后只替换原生本应匹配的内容；在独立临时夹具中验证替换边界，不在用户笔记上测试。
5. Open file 中文文件名／别名、模糊不连续匹配、路径、不同长度映射、高亮与实际打开；最近文件、重复候选、类型过滤、忽略降权及创建动作不被破坏。
6. 多面板、延迟视图、重复开关窗口、另一插件钩子及卸载恢复；构造失败／超限时保留原生行为并有明确诊断。
7. 在 macOS 独立实例做真实输入及点击；可用桌面移动布局辅助观察，但不把它当 iOS WebKit 真机验证。iOS 最终由用户复测，Android 不虚构通过。
8. 记录代表性文件名／别名数量下的耗时与预算回退，不凭小库宣称大库性能。

全部桌面验收通过后才用现有安全安装器更新批准测试库，备份旧插件产物并核对非产物文件不变。安装器不修改用户 data.json；旧库保存过 false 时保持关闭，用户可自行开启。更新仍保留 `cjk-search-probe` ID，不创建第二个同时修改搜索的插件。

## 10. 自审与下一步

- 已把全库、Find、Open file 的不同语法、匹配与坐标区分；不能直接套一个正则包装。
- 明确不增强替换；切换后旧游标泄漏是数据安全验收项，而非只看 UI 是否隐藏替换按钮。
- 默认开启与保留旧 false 不冲突；关闭插件新增关系不等于关闭原生固有能力。
- 设计阶段没有将静态源码观察冒充运行验证；现在的实际验收结果单独记录在验证报告中。
- 不复制闭源实现、不添加索引／界面框架、不使用子代理或 Git 操作。

实现和桌面验收已完成，安装保留了全部非产物文件及原设置。下一步由用户重新启用 0.2.0，复测实际使用体验和 iOS 两个新入口；不将已有 0.1.0 iOS 全库验收外推为新入口通过。
