# Graph View 字符等价搜索设计

状态：用户已批准功能边界，并明确要求直接实施、简化流程，不再单独等待实施计划审批。按“原生基线／预期失败 → 实现与回归 → 验收后安全安装”执行。现已完成 0.4.0 桌面验收与测试库更新，见 [验证报告](../../research/graph-view.md)。以下保留设计阶段的目标与门槛；本轮主会话执行，无子代理、分支、提交或推送。

## 1. 目标与范围

在原生全局图谱和局部图谱中复用既有 Unicode 18.0.0／OpenCC 1.4.2 字表，让等价字符参与 **Filters** 的节点筛选和 **Groups** 的颜色分组。输入、节点名称、真实文件身份、链接关系及图谱控制仍由 Obsidian 管理。

用户明确要求高级筛选可选开启、默认关闭，并已确认：

- **Graph view** 默认开启，覆盖两个图谱入口的普通文本。
- **Advanced graph queries** 默认关闭；开启后扩展 `path:`、`file:`、`tag:` 条件中的字面文字，仅作用于 Graph View。
- `-file:体` 开启高级增强后也排除文件名含 `體` 的文件；不把增强定义成“最终结果只能增加”。
- 标签层级、布尔逻辑、大小写控制与显式正则仍遵守原生语义。其他高级条件不增加字符等价能力。
- 异常或超限回退完整原生查询，不返回半增强结果。

不改变已交付的全库 Search、Markdown Find、Quick switcher 的语法或开关行为；不扩展替换，不增加图谱 UI、文件索引、词汇转换或新数据来源。

## 2. 设置及用户界面

沿用当前原生英文设置和集中字符串，不引入 i18n 框架。

| 设置键 | 标签 | 缺失／非法值默认值 | 作用 |
| --- | --- | --- | --- |
| `graphEnabled` | Graph view | true | 全局／局部图谱的 Filters 和 Groups |
| `graphAdvancedQueries` | Advanced graph queries | false | Graph 的高级条件字面值与受支持的组合查询 |

在 Search enhancements 中紧接 Quick switcher 添加这两项。推荐说明：

- Graph view: `Match equivalent characters in global and local graph filters and groups.`
- Advanced graph queries: `Also match equivalent characters in path:, file:, and tag: filters. Exclusions also include equivalent forms. Requires Graph view enhancement.`
- 核心图谱未启用：`Enable Graph view in Core plugins to use this feature.`

高级选择可以预先保存；Graph view 关闭时它不生效，也不被重置。继承已有串行保存、失败回滚、保留无关字段和不在加载时写设置的规则。不会替用户开启核心 Graph view。

两项均受现有 **Compatibility characters** 控制。关闭兼容字符只撤销插件额外的全量关系，不剥夺原生已有匹配。

## 3. 原生结构：已观察事实与待验证接入点

只读检查本机 Obsidian 1.13.7 打包源码，确认：

1. 全局图谱通过 `view.dataEngine`，局部图谱通过 `view.engine` 使用同一种数据引擎。
2. `updateSearch()` 读取主过滤框和颜色分组，交给 `setQuery()`；界面与保存选项来自原始控件值。
3. `setQuery()` 为各查询创建原生查询对象，保存为 `searchQueries`，随后通过异步队列读取文件、计算 `fileFilter` 并调用原生渲染。
4. 主过滤决定纳入范围，颜色组按照原生顺序决定颜色。渲染另有附件、标签、未解析链接、忽略文件、孤立节点及局部图谱范围规则。
5. 原生解析结果保留文字／引号／正则等 token，以及组合和条件匹配器。`path:` 与 `file:` 限制匹配字段；`tag:` 使用专用匹配，读取元数据并保留完整标签／子标签边界。
6. 原生 `tag:` 对可接受的参数有专门限制，不能简单把它改写成 `tag:/.../`。本插件不放宽原生语法合法性。

这些是源码观察，**不是 Graph 增强已实测**。拟在引擎实例的 `setQuery()` 接入：原生完成解析后、第一份文件或标签被实际匹配前，为本次查询的受支持文字匹配部分安装等价模式。必须先在隔离真实实例证明该时序、结构识别和资源需求成立。

不依赖打包后的压缩类名、界面翻译或全局原型。不复制原生词法分析器／图谱渲染器，也不替换查询构造器的全局引用。若安全的实例级接入无法成立，停止该路径并报告差异，不改用输入重写或伪造元数据。

## 4. 查询行为

### 高级增强关闭

采用现有全库 `expand` 的保守语法边界：仅增强可安全识别的连续普通字面文本。带条件、空白组合、括号、引号、否定或显式正则等查询完整保持原生，即使其中含可映射字符。

普通文本增强同时适用于 Filters 和 Groups。空查询及空颜色组保持原生，不人为创造匹配。

### 高级增强开启

在原生已解析结构上限定可增强范围，不重新解析用户字符串：

- 增强普通文字叶节点，以及 `path:`、`file:`、`tag:` 所允许的文字值。
- 在原生支持的 AND（空白组合）、OR、括号、否定和大小写控制下保留同一逻辑结构、优先级与生效范围。
- `path:`／`file:` 中原生合法的引号文字保留其原有字段和精确文字语义；不将引号去除后当成另一种查询。
- 显式正则叶节点不变，不扩展其模式中的汉字；也不将映射结果解释为新运算符、正则或属性语法。
- `content:`、`line:`、`block:`、`section:`、任务条件和属性条件等其他已识别原生子树不增强，也不穿过这些边界增强里面的文字。
- 混合条件可以只增强支持的部分。例如 `file:体 content:研究` 的文件名条件增强，正文条件保持原生。这是明确的范围选择，不是失败后的部分提交。
- 遇到无法可靠识别的结构或无法保持语义的节点，整条查询回退原生。

例子：

| 查询 | 高级关闭 | 高级开启 |
| --- | --- | --- |
| `体` | 追加 `體` 等等价命中 | 相同 |
| `file:体` | 原生 | 文件名中的等价文字；不会改成目录或正文搜索 |
| `path:"研究目录"` | 原生 | 路径字段内的等价文字，保留原生引号规则 |
| `tag:研究` | 原生 | 等价标签及其原生允许的子标签；不是任意子串匹配 |
| `-file:体` | 原生 | 原生否定作用于增强后的文件名条件 |
| `file:体 OR tag:研究` | 原生 | 各条件分别增强，OR 不变 |
| `file:/体.*/` | 原生 | 原生正则，不扩展 |
| `content:体` | 原生 | 原生，不扩展 |

## 5. 保留原生匹配、标签及图谱规则

增强发生在受支持文字匹配部分，保留该部分原有匹配能力。不能在整条查询执行后简单并集“原生结果＋增强结果”，否则会破坏否定、主过滤与颜色组优先级。

- 保持原始查询字符串、解析 token、文件和节点标识；只对当次查询实例做受限的内部匹配调整。
- 大小写参数以原生当前作用域为准，不能统一按忽略大小写展开后再套大小写敏感条件。
- 标签继续来自原生 metadataCache：正文标签与 frontmatter 标签沿用原生读取规则，不自行扫描正文或生成标签。
- 保留标签开头与子标签的结构边界。例如查询 `tag:研究` 不得因为增强而匹配 `#研究者`；`#研究/体` 的子标签规则仍由原生决定。不能让等价标点意外制造、消除层级边界；无法保证边界的展开按整条查询回退。
- 保留主过滤与各颜色组的原始顺序、颜色和优先级；不改分组排序。
- 局部图谱保留中心文件及原生深度、入链、出链和邻居规则。增强过滤不等于扩大遍历半径。
- 附件、标签节点、未解析节点、忽略文件、孤立节点和时间推移渲染均保留原生资格规则。增强只改变原生确实执行字符查询的位置，不额外为未解析节点构造文件结果。
- 不重置缩放、平移、布局参数或物理模拟；命中集合改变造成的原生布局变化不属于改写布局。

## 6. 边界、原子性及异步安全

复用 `src/matcher.js` 的数据和有界展开，不改变其现有入口语义。原生解析需要的资源必须在增强前后相容，不能因调整内部模式漏读正文或元数据。

每条主过滤／颜色组查询分别作为一个原子单位：

- 原始查询最多 256 个码位。
- 同一查询各增强片段合计受 65,536 个 UTF-16 模式单元和 4,096 个展开分支节点预算约束；另以 4,096 个访问节点限制解析树遍历，循环结构直接回退。
- 先收集、校验和生成全部调整，再提交；任一超限、只读字段或接口错误均恢复该条查询的全部改动。若回滚本身无法保证，废弃该次增强并重新建立原生查询，不继续运行半改对象。
- 某个颜色组回退不会删除该组或改变其位置；其他独立查询按自己的模式运行。不是截断组列表或候选列表。
- 不为字符组合反复全库扫描，不引入常驻笔记索引。复杂度与原生查询数量加各自有界的展开工作量相关；不宣称无限颜色组没有成本。
- 后续查询必须取消或隔离旧队列，不能让旧异步结果覆盖新查询、设置或关闭后的结果。

缺失字表、接口不支持或增强失败时保留原生查询和图谱；不额外修正原生本来就无效的语法。

## 7. 生命周期与设置生效

沿用现有 workspace／document 发现方式，覆盖已打开、后打开及实际加载后的图谱实例。未加载的占位视图先等待，不误报为不兼容。

- 每个实例只安装一次，不给原生类的 prototype 打补丁。
- 关闭 Graph 增强或卸载时，退役包装立即失效；即使其他插件保留旧包装引用，重新启用也不能令旧包装复活。
- 只恢复仍由本插件拥有的方法和内部调整；不覆盖其他插件后来安装的钩子。
- 对仍打开的图谱，关闭／重新开启或改变高级模式后，从未改写的原始查询重新建立相应结果；由原生队列负责取消旧计算。重算本身不改输入或保存原生图谱配置。
- Compatibility characters 对 Graph 的新计算生效；不为本次功能改变其他入口既有的“下一次搜索生效”约定。
- 关闭视图／窗口、核心 Graph 被关闭或重建时清理监听与实例记录；不继续刷新已销毁引擎。

诊断继续使用 `[CJK-Probe]`，区分全局／局部图谱及过滤／分组，仅记录状态、数量、耗时和固定失败类别。不输出查询、文件名、路径、标签、笔记内容、颜色组文本或私密异常详情。

## 8. 最小实现职责

- 新增 `src/graph.js`：受限查询增强、实例发现、图谱生命周期与回退。先放在一个模块，不引入通用适配器框架。
- `src/main.js`：两个布尔设置、保存和生命周期接线、诊断状态。
- `src/strings.js`：两行设置及核心未启用提示的英文文案。
- 复用 `src/matcher.js` 和 `src/documents.js`；确需修正共享逻辑时保留所有既有回归，不顺带扩大全库高级语法。
- 图谱测试复用现有隔离 Obsidian 实例启动器；增加目标夹具／检查，而不是另一套启动、安装或备份工具。

## 9. 验收及交付条件

先固定原生基线和预期失败，再实现。必须分别验证高级关闭与开启，不用“输入框里能打字”代替实际图谱结果。

1. 真实实例验证接入时序：第一批文件匹配前已装配增强；输入、保存的过滤／分组字符串不被临时重写。
2. 全局与局部、Filters 与 Groups 均有正反例；检查节点集合、颜色分配、分组优先级及点击打开真实文件。
3. `体／體`、`发／發／髮`、既有多义组、兼容模式差异、多字符序列及非 BMP 字符；原生基线能力不被关闭兼容开关剥夺。
4. `file:` 与 `path:` 字段隔离、引号、AND／OR／括号／否定、大小写控制；显式正则与未支持高级子树保持原生。
5. 标签正文／frontmatter、可选 `#`、完整与子标签、前缀反例、层级分隔符；原生拒绝的标签参数仍不被插件接受。
6. 局部中心与深度、连线方向、孤立点、附件、标签节点、未解析链接及忽略规则不被插件替代。
7. 快速连续输入、异步读取与设置变化、元数据更新、多面板、关闭／重开、核心插件启停、外来钩子、卸载与重新启用。
8. 默认 true／false、旧选择与无关字段保留、读取／保存失败、不写加载迁移；真实 UI 及 Graph 独立开关不影响其他三个入口。
9. 查询长度、总模式长度、分支与遍历预算边界；注入接口和提交失败时完整回退，不出现半增强或无界遍历。
10. 既有 Python／Node、全库、Find／Quick switcher、设置和安全安装回归全部保留。对代表性图谱／分组规模测量增量开销，明确测试规模，不把小库外推为大型仓库性能。

桌面验证仅在临时库及自有实例进行。通过后再用既有 allowlist 安装器更新批准测试库，安装前重新快照并备份，核对已测试哈希及所有非产物文件不变。保留 `cjk-search-probe` ID；不操作用户正在运行的实例。

iOS 需要用户明确真机验收；Android／Windows／Linux、其他 Obsidian 版本及完整 popout／IME／无障碍矩阵不能从桌面测试外推。
